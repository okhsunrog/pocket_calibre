# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Клиент calibre content server для электронной книги PocketBook 632 (Touch HD 3)
на Rust + Slint. Пользовательская документация — в `README.md`; здесь то, что
нужно для разработки и чего в README нет. Комментарии, README и сообщения
коммитов — на английском. Русские комментарии и README, оставшиеся от первых
версий, переводятся по мере правок; сам этот файл тоже ждёт перевода.

## Команды

```sh
cargo check                 # быстрая проверка (хост)
cargo clippy --all-targets  # держать чистым — в проекте нет warnings
cargo test                  # юнит-тесты в src/calibre.rs и src/config.rs
./build-arm.sh              # кросс-сборка под armv7 → dist/pocket_calibre.app
```

Хостовая сборка (`cargo build`) компилируется и проходит тесты, но сам бинарник
на хосте не запустить: `inkview::load()` грузит `libinkview.so`, которой на
десктопе нет. Логику без inkview (calibre-клиент, конфиг) проверяют юнит-тесты.

Кросс-сборка требует `cargo-zigbuild` + `zig` (не C-тулчейн: libinkview
линкуется в рантайме). Цель — `armv7-unknown-linux-gnueabi.2.23`.

## Деплой и отладка на устройстве

Роутер (Xiaomi) изолирует Wi-Fi-клиентов друг от друга — напрямую с ноутбука до
читалки не достучаться. Рабочий канал — мост через телефон: `ноутбук →(adb)→
телефон →(хотспот)→ читалка`. Устройство джейлбрейкнуто (pbjb), root+SSH.

```sh
./tunnel.sh    # SSH-тоннель до читалки (нужен adb + телефон с хотспотом)
./deploy.sh    # сборка + заливка (cat-over-ssh, не scp) + сверка md5
./shot.sh out.png   # запуск + вывод на передний план + скриншот
```

`ssh pocketbook` — алиас в `~/.ssh/config` (ключ + legacy-опции под dropbear
2016). При смене адреса читалки: `READER_IP=... ./tunnel.sh`.

**Полный агентский цикл** (менять вёрстку и проверять самому, без человека) —
это `shot.sh`. Ключевые нюансы, на которые уходит время при переоткрытии:
- Голый `exec` .app по SSH **не выходит на передний план** — процесс живёт,
  рисует в свой буфер, но панель показывает десктоп. Форграунд даёт
  `iv2sh SetActiveTask <pid> 0`, причём pid должен быть **ровно один** (иначе
  `pidof` вернёт несколько и аргументы SetActiveTask поедут).
- Скриншот — чтение `/dev/fb0` (8-бит серый, **1448×1072 landscape**), потом
  поворот на -90° в портрет. `iv2sh SaveBitmap` в CLI **нет**.
- Приложение получает `EVT_INIT` и полноценно работает при запуске по SSH
  (пишет, например, `/dev/fb0`), так что диагностику можно снимать без меню.

## Архитектура: три потока

`main()` устраивает три исполнителя, потому что здесь **два блокирующих цикла
событий**, каждый владеет своим потоком, и ни один нельзя вложить в другой:

1. **Поток inkview** (`main`) — `inkview::iv_main` → C-цикл `InkViewMain`,
   не возвращается до выхода. Его замыкание фильтрует события и шлёт их в канал.
2. **UI-поток** (`ui_main`) — цикл событий Slint через `inkview_slint::Backend`.
   Владеет окном, `Pager`, конфигом, `slint::Timer`.
3. **Worker** (`worker`) — блокирующий HTTP к calibre, чтобы не морозить UI.

Обмен — каналами `mpsc`:
- `Event` (inkview → UI): пользовательский ввод в бэкенд Slint.
- `Cmd` (UI → worker): Refresh / Download / Reconfigure / Covers.
- `Msg` (worker → UI): Status / Busy / Books / BookState / Cover.
- `Answer` (клавиатура → UI): результат ввода текста.
- `redraw` (inkview → UI): `EVT_REPAINT`/`EVT_SHOW` → полная перерисовка.

**Результаты забираются `slint::Timer` (250 мс), а не `invoke_from_event_loop`.**
Бэкенд inkview-slint не реализует event loop proxy, и `invoke_from_event_loop`
из чужого потока **паникует**. Таймер же крутит сам цикл бэкенда — это
единственный вход на UI-поток извне. Цена: цикл не спит дольше 250 мс.

`iv: &'static Inkview` — через `Box::leak`: `Screen<'a>`, бэкенд и worker хотят
`'static`, один leak на процесс закрывает всё (как в примерах inkview).

## Подводные камни (иначе переоткрываются часами)

**SDK под прошивку.** `inkview`/`inkview-slint` собраны с фичей `sdk-6-5` —
это **текущая** прошивка (Настройки → Версия ПО = U632.6.5.x). НЕ верь
`/mnt/secure/fwinfo.txt` на устройстве: он датирован 2019 годом и показывает
заводскую 5.19. При смене прошивки правится в обеих зависимостях в `Cargo.toml`.

**SDF-шрифты обязательны.** `build.rs` включает `with_sdf_fonts(true)`. При
растровом встраивании компилятор Slint берёт размеры глифов только из
**литеральных** `font-size` в px (`collect_font_sizes_used`), а у нас все
размеры вычисляются из миллиметров — встроился бы один дефолтный 12px-атлас, и
текст не масштабировался бы вообще (кнопки-геометрия растут, шрифт нет). SDF
рендерит любой размер из одного представления.

**Вёрстка в миллиметрах, не в долях экрана.** `ui/app.slint` задаёт всё через
`Metrics.mm` (логических px в 1 мм). Значение считает Rust из реального dpi
(300, снят с устройства) и `scale_factor` и пишет в global. Нельзя выводить
масштаб из `window().size()`: у этого бэкенда `size()` возвращает **логический**
размер (357×482), а не физический — делить его на scale = схлопывать вёрстку.

**Кириллица встраивается вручную.** Slint встраивает глифы только для латиницы,
цифр и строковых литералов из `.slint`. Названия книг приходят из Rust, поэтому
кириллический алфавит перечислен литералом в `glyph-set` в `ui/app.slint` —
иначе на месте текста пустые прямоугольники.

**Пагинация, а не прокрутка.** Прокрутка на e-ink через inkview-slint
нерабочая (цикл обрабатывает одно событие за кадр, палец даёт ~50
PointerMove/с — очередь растёт быстрее, чем разгребается). Список нарезается на
страницы в `Pager` (src/main.rs), число строк считает Slint (`rows-per-page`),
`PointerMove` в бэкенд **не пробрасывается** вовсе. Листание — экранными и
аппаратными кнопками (inkview-slint отдаёт их как стрелки).

**Клавиатура — на потоке inkview.** `OpenKeyboardEx` модальна и требует потока
`InkViewMain`. Вызов туда переносится через `iv.SetWeakTimerEx` (одноразовый
колбэк на потоке inkview) — см. `src/keyboard.rs`. Из UI-потока звать нельзя.

**libm-шим.** `src/libm_shim.rs` определяет `fminimum_num`/`fmaximum_num` —
tiny-skia (через resvg) использует `f64::minimum`, Rust лоуерит это в libm C23,
которых нет в glibc 2.23 устройства.

**i18n: два механизма, не один.** Строки из `ui/app.slint` переводит сам
Slint: литералы обёрнуты в `@tr()` (исходный язык — английский), русский
каталог — `lang/ru/LC_MESSAGES/pocket_calibre.po`, встраивается в бинарник
через `with_bundled_translations` в `build.rs` (gettext в рантайме на
устройстве нет). msgid обязан байт-в-байт совпадать с литералом — иначе
строка молча останется английской. Дефолтный gettext-контекст (имя
компонента) выключен `DefaultTranslationContext::None`: с ним каждой записи
нужен был бы `msgctxt "MainWindow"`, и переименование компонента молча
роняло бы весь перевод; `msgctxt` в .po не писать. Строки со стороны Rust (статусы, состояния
книг, номер страницы) ходят по каналам **данными** (`i18n::Status`,
`i18n::BookState`) и переводятся только на UI-потоке в `src/i18n.rs` — иначе
смена языка не перерисовала бы их. Язык прошивки читает `currentLang()`
**только на потоке inkview** (шлётся в канал при `EVT_INIT` и по клавише
`LanguageChange`); поле гварится через `.as_ref()` — сгенерированный метод
паникует, если символа нет. `slint::select_bundled_translation` зовётся
строго после `MainWindow::new()` и только с UI-потока. Смена языка нарочно
не шлёт `Cmd::Reconfigure` (сбросил бы список книг).

**fontconfig в графе, но не линкуется.** `fontique` в прямых зависимостях с
фичей `fontconfig-dlopen` нужен только чтобы `yeslogic-fontconfig-sys` грузил
libfontconfig через dlopen, а не звал pkg-config (тот рушит кросс-сборку без
sysroot). На устройстве библиотеки нет — fontique штатно отдаёт пустой набор.
Не удалять и не «чистить» эту зависимость.

## Идентификатор сборки

`build.rs` пишет `BUILD_ID` (день-ЧЧММ UTC), он виден в статусбаре приложения.
Служит для сверки, какой билд реально запущен на устройстве. Обновляется каждую
сборку.

## Незакрытое

- **Изоляция клиентов на роутере** — читалка не видит calibre в домашней сети;
  тестируется только через хотспот телефона. Это сторона сети, не кода.
- **Перерисовка после клавиатуры** — сделана через `repaint-tick`, живьём ввод
  текста на устройстве не проверялся.
- **usbnet** как запасной канал деплоя не поднят (USB был в режиме флешки).
- **i18n не проверен на устройстве.** Реализация есть (см. раздел про два
  механизма), но живьём не гонялась: формат строки `currentLang()` на PB632
  неизвестен (нормализуется по префиксу `ru*`, при сюрпризе править
  `i18n::Lang::normalize`; сырое значение можно залогировать и снять через
  `/tmp/pc.out`), и доставка клавиши `LanguageChange` при смене языка в
  системных настройках не подтверждена (безобидно: язык подхватится при
  следующем запуске).
- **`NetConnect` зовётся с рабочего потока** (`net::ensure_online`, вызовы из
  `worker`). Это тот же класс вызовов, что и `OpenKeyboardEx`: он показывает
  системный модальный диалог, а такие вызовы inkview ждёт на потоке
  `InkViewMain`. Работает, но правилу из `src/keyboard.rs` противоречит.
  Правильно было бы прогнать через тот же трамплин `SetWeakTimerEx` — переделка
  требует проверки на устройстве, поэтому пока как есть.
